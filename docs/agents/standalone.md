# サンプルゴーストから独立させるとき

サンプルゴースト（ポストと狛犬）を改造して、自分のゴーストとして配布するときは、少なくとも次を変える。このゴースト固有の項目は、`GHOST.md` の「テンプレートから独立させるときの追加項目」に書かれている。作者に何を聞き、どの順で進めるかは `docs/agents/workflows/new-ghost.md` にある。

- [ ] `ghost/master/descript.txt`: `name`、`sakura.name`、`kero.name`、`craftman`（半角英数）、`craftmanw`、`craftmanurl`、`id`
- [ ] `install.txt`: `name`、`directory`（インストール先のフォルダ名。半角英数で、他のゴーストと重ならないもの）
- [ ] ネットワーク更新の URL（`dic06_String.txt` の `＠homeurl`）。自分の URL に変えるか、更新しないなら消す。**元の URL のまま配布すると、元のゴーストの更新で、改造した内容が上書きされてしまう。**
- [ ] シェル: 元のシェルの利用条件を `GHOST.md` で確かめる。改変した画像の配布が許されていなければ、自作のシェルか利用許可のあるシェルに差し替え、シェルの `descript.txt`（`name`、`craftman` など）も変える。
- [ ] `readme.txt`（原作者の readme。自分のゴーストの説明に書き直す。原作者への謝辞やクレジットは残してよい）、`README.md`、`thumbnail.png`、`delete.txt`（元のゴーストの更新用なので、自分のゴーストに合わせて見直す）
- [ ] 名前やキャラクター設定に関わる台詞（初回起動の自己紹介、ランダムトーク、マウスへの反応など）
- [ ] 実験用の辞書（`dic08_Labo.txt` など）と、使わない SAORI（`satori_conf.txt` の `＠SAORI`、`saori/`）
- [ ] `GHOST.md` を、自分のゴーストの内容に書き直す
- [ ] GitHub の自動リリースなど、元のゴーストから引き継いだワークフロー
- [ ] `satori_license.txt` は、`satori.dll` を同梱する限り残す（里々のライセンスは変えてはならない。辞書などは対象外）
- [ ] 元にしたサンプルゴーストと里々のクレジット（義務ではないが、慣習としておすすめ）
